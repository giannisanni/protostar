# protostar: 125M Prototype Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Train a ~130M-parameter LLM on substrate's 2x RTX 5060 Ti that ablates every recipe-v4 piece (GDN hybrid, MTP, Engram-lite, then PLE/LAuReL/AltUp/LLM-JEPA), producing a ranked list of what earns its place in the 350M+ run.

**Architecture:** Deep-thin decoder (d=640, 24 layers, tied GPT-2 vocab embeddings), 3:1 Gated DeltaNet : full attention, Muon on hidden matrices + AdamW on embeddings/head, WSD schedule so ablations branch from one shared stable-phase checkpoint. Single file model, config-driven ablation flags.

**Tech Stack:** PyTorch 2.13 cu130 (Blackwell sm_120), `flash-linear-attention` (GDN Triton kernels), vendored `muon.py` (Keller Jordan), pre-tokenized FineWeb-Edu GPT-2 shards, torchrun DDP. No wandb — CSV logs + matplotlib.

**Design source:** vault note `training-a-small-llm-from-scratch-in-2026-...` (recipe v4). Hetero-GPU constraints: vault note `training-on-mismatched-gpus-...`.

**Hardware ground rules (from the hetero-training research):**
- Prototype uses ONLY the two identical 5060 Tis. The 4060 Ti stays on pulsar duty. No heterogeneity problem, by construction.
- One 5060 Ti is behind a Gen3 x1 chipset link until the MCIO adapter lands. For a 130M model that's ~260MB of bf16 grads ≈ 0.3s per all-reduce over x1. Gradient accumulation 8-16 amortizes this to noise. Task 4 measures it; if step time is >15% comm, raise accum.
- Runs need `df -h` headroom checks and possibly serve stopped (host RAM). Task 0 verifies, never assumes.

**Token budgets:** sanity = 100M tok (~30 min), ablation = 2B tok (~overnight per run), final combo = 5B tok (~30h). 6ND math, measure real tok/s in Task 4 before trusting.

## Phase 2: Baseline model + trainer

### Task 2: Model core (dense baseline)

**Files:**
- Create: `model.py` (ONE file: config + all modules)
- Test: `tests/test_model.py`

Config dataclass (every ablation is a flag, defaults = dense baseline):

```python
@dataclass
class Config:
    vocab: int = 50304          # GPT-2 padded to /128
    d: int = 640; n_layer: int = 24            # deep-thin (MobileLLM)
    n_head: int = 10; n_kv_head: int = 2       # GQA
    ffn_mult: int = 4                          # ReLU^2 MLP (speedrun)
    rope_ratio: int = 4                        # every 4th layer NoPE (iRoPE)
    attn_sink: bool = True                     # learned per-head sink logit
    qk_norm: bool = True
    gdn_ratio: int = 0          # 0=dense; 4 = 3:1 GDN:attn (Task 5)
    swa_fallback: bool = False  # sliding-window instead of GDN if fla broken
    mtp: bool = False           # Task 6
    engram: bool = False        # Task 7
    seq_len: int = 2048
```

Modules: RMSNorm, RoPE, GQA attention with sink bias + zero-centered QK-norm, ReLU² MLP, tied embedding/head. ~130M params dense (embedding 32M + 24 x ~4.1M).

**Step 1: Failing tests** — `test_param_count` (120M < n < 140M), `test_forward_shape` ((2,64)->(2,64,50304)), `test_causality` (perturbing token t doesn't change logits < t).
**Step 2:** FAIL. **Step 3:** Implement. **Step 4:** PASS. **Step 5:** Commit `feat: dense baseline model`.

Optimizer split (the only subtle part — get it exactly right):

```python
hidden = [p for n,p in model.named_parameters() if p.ndim == 2 and "embed" not in n and "lm_head" not in n]
rest   = [p for n,p in model.named_parameters() if p not in set(hidden)]
opts = [Muon(hidden, lr=0.02, momentum=0.95),
        torch.optim.AdamW(rest, lr=3e-4, betas=(0.9,0.95), weight_decay=0.0)]
```

## Phase 3: Recipe pieces (one task = one flag = one ablation arm)

### Task 5: GDN hybrid (`gdn_ratio=4`)

**Files:** Modify `model.py` — layer i uses `fla.layers.GatedDeltaNet(d_model=640, ...)` when `i % 4 != 3`, full attention every 4th (Qwen3.6 layout). Attention layers keep RoPE; GDN layers carry position implicitly.
**Test:** `test_gdn_forward` (shape + causality with GDN on), `test_gdn_param_parity` (within 10% of dense count — shrink ffn_mult on GDN layers if needed).
**Check on substrate:** 100M-token sanity run, loss curve overlays dense baseline (expect ≈parity at this budget; the win is speed + it's what pulsar serves). Commit `feat: gdn hybrid`.
If fla breaks on sm_120: set `swa_fallback=True` path (window 512), note it, move on.

### Task 6: MTP head (`mtp=True`)

**Files:** Modify `model.py` — one extra lightweight block (RMSNorm + linear merge of h_t and emb(t+1), one attention-free MLP) predicting token t+2 through the tied head; loss = ce_main + 0.3 * ce_mtp (DeepSeek λ). ponytail: depth-1 MTP only; pulsar's nextn verify wants exactly this shape.
**Test:** `test_mtp_loss_drops` (overfit test with mtp on converges; main-head loss within noise of baseline overfit).
Commit `feat: mtp head`.

### Task 7: Engram-lite (`engram=True`)

**Files:** Modify `model.py`:

```python
# hash(prev, cur) -> 2 heads x 2^18 buckets x 64d, gated by hidden state
idx = (prev_tok * 1000003 + cur_tok) % (1 << 18)
mem = torch.cat([table_h(idx) for table_h in self.tables], -1)   # (B,T,128)
h = h + torch.sigmoid(self.gate(h)) * self.proj(mem)             # inserted after layer 8
```

~33M table params — sparse-access, report separately from dense count (Engram's point: params without FLOPs).
**Test:** `test_engram_gate_zero_init` (proj zero-init → step-0 logits identical to engram-off; nothing breaks at init).
Commit `feat: engram-lite`.

## Execution log 2026-07-29 (deviations from plan)

- **Attention sinks defaulted OFF**: the sink-KV + explicit-mask implementation
  forces the math SDPA backend and OOMs 16GB at any usable batch. Correct
  reimplementation = flex_attention with `out * sigmoid(lse - sink)` rescale.
  Moved to the Task 9 ablation queue.
- **Chunked CE added**: full logits (B*T x 50304) never materialize; per-chunk
  checkpointed head. Required to fit 16GB at all.
- **Micro-batch 4, accum 16/rank** (not 16/8): 24-layer activations + autocast
  fp32 norm copies dominate. Activation checkpointing is the lever if bigger
  micro-batches are ever needed.
- **WSD-branch correction**: branching one stable checkpoint only works for
  same-architecture ablations. Architecture arms (dense/gdn/mtp/engram) each
  get a full 2B-token run with own decay — ablate.sh does this.
- **fla GDN proven on sm_120** (fwd+bwd) — swa_fallback flag deleted.
- **GDN param parity**: expand_v=1 + ffn_mult-1 on GDN layers keeps the arm
  in the 125M class (test-enforced).
- **Val loss = main-head CE only** (MTP arm would otherwise report its aux
  term and corrupt the comparison).
- Bench: 19.6k tok/s single 5060 Ti; 36.4k DDP with bf16 compression hook
  (1.86x over the x1 link). Loss identical single-vs-DDP at same seed.

## Phase 5 (deferred to the bigger run, decided 2026-07-30)

**Finding:** we train on plain FineWeb (Karpathy/kjj0 pre-tokenized shards),
NOT FineWeb-Edu. Sampling the dense checkpoint shows the cost directly:
"the capital of France is" continues into hotel-booking SEO copy, because
that genre dominates unfiltered Common Crawl. Recipe v4 called for
FineWeb-Edu; pre-tokenized convenience overrode it.

Fix, when the 350M run happens: FineWeb-Edu backbone + Wikipedia (5-10%,
upsampled) + FineMath/MegaMath + code/StackExchange. Wikipedia ALONE is
worse (single narrow register, ~4B tokens). Requires tokenizing
HuggingFaceFW/fineweb-edu ourselves (no public GPT-2 shards — 401) which is
the GigaToken job already scheduled for that run.

**Two constraints:** (1) never change data mid-ablation — identical inputs
are what make the architecture comparison valid; (2) **val loss cannot
compare data mixtures** (each model wins on its own distribution) — needs
downstream evals (HellaSwag, ARC-easy), which are not wired up yet.

Expectation: at this scale this is a bigger quality win than any of the four
architecture arms.
