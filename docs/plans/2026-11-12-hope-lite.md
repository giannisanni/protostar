# hope-lite: Nested Learning's CMS + the write-gradient fix (pre-registered)

Source: Behrouz & Mirrokni, "Nested Learning: The Illusion of Deep Learning
Architectures" (NeurIPS 2025). Hope = self-modifying Titans + Continuum
Memory System (MLP levels at different update periods). The paper's
anti-forgetting argument is structural (slow levels keep what fast levels
overwrite). Our v2 rounds say the binding problem is different: TBPTT
detaches the state, so a probe's loss never reaches the projections that
WROTE the fact. This round tests both claims, separately and together.

## Arms (all init from `runs/v2_persist/ckpt_003000.pt`, same data and budget as v2_curr)

| arm | GPU | memory | bptt across windows | readback aux |
|---|---|---|---|---|
| hope_full | 0 (5060 Ti) | CMS 3 levels: period 32/128/512 tok, decay .99/.995/.999 | K=2, slow levels only | 0.1 |
| cms_only | 1 (5060 Ti) | same 3 levels | none (detached, as v2) | 0 |
| fixes_only | 2 (4060 Ti) | single level, period 32 | K=2 | 0.1 |

- CMS = independent (head-wise) variant, eq. 74; learned weighted sum, init
  w = [1, .1, .1]. Every level is seeded as a COPY of v2's trained memory
  (nested-CMS init), then diverges by period.
- Slow levels carry pending gradient across calls and update once per period
  (eq. 71); the 512 level updates once per window.
- Readback = InfoNCE (temp 0.1, 64 sampled keys): after each update, can the
  new state still retrieve the PREVIOUS update's values? Contrastive so it
  cannot be gamed by collapsing v. Chance = ln 64 = 4.16.
- Budget: 3000 steps x 131k tok = 393M tokens, window 512, batch 8, accum 32
  (same tokens/step as v2_curr's 16x8x2 ranks), cur_every 4, reset_prob
  .0625, muon .005 / adam 1e-4, warmup 100, decay from 2000.
- K=4 OOMs 16GB at batch 8 (measured); K=2 peaks 15.3GB. So bptt only
  directly trains age-1 probes. Ages 2+ show whether it generalises.
- New code verified bit-exact against the old FastMemory on the old config.

## Decision metrics (final checkpoints, currprobe ladder)

1. WRITE-GRADIENT claim (hope_full and fixes_only, age-1 contribution):
   - >= +10pp: the detach was the bottleneck; validated, raise K next
   - +4 to +10pp: partial; one round (K via activation checkpointing, or aux weight)
   - < +4pp: cross-window bptt at K=2 is not enough; documented negative
2. CMS claim (cms_only vs v2_curr, overall contribution):
   - >= +5pp overall: multi-timescale alone helps retrieval (paper's claim holds here)
   - < +5pp: CMS without write gradient does not fix it (our structural claim)
3. Interaction: hope_full minus fixes_only on age 2-3 and 4+. Positive (>= +4pp)
   = slow levels extend what bptt teaches beyond its K-window horizon.
4. Secondary: `oneshot.py --curriculum` mechanism (>=30 / 5-30 / <5%) and
   standard transfer, same thresholds as the curriculum round.

Report the full ladder for every arm, never one number.

## Guards

- fresh-memory FineWeb val <= 3.55 (v2_curr 3.46). The readback aux backprops
  into the backbone via wk/wv(h); a val rise in the aux arms alone points there.
- gate not collapsing; CMS weights w logged (slow levels pruned to ~0 = model
  rejected them; that is a result, not a bug).
- readback aux must end below 4.16 (chance), else the readback never trained.
- NaN guard active; units auto-resume from the newest checkpoint (every 500).

## RESULTS (2026-11-12)

Harness check first: v2_curr loaded as a 1-level MemoryStack reproduces its
ladder exactly (+2.2 / +1.4 / +1.4 / +6.3), so the stack eval path is sound.

| arm | val | fresh first-tok | contribution all | age 1 | age 2-3 | age 4+ |
|---|---|---|---|---|---|---|
| v2_curr (baseline) | 3.46 | 9.2% | +2.2 | +1.4 | +1.4 | +6.3 |
| cms_only | **3.94** (guard FAIL) | 4.8% | -0.1 | -0.2 | +0.0 | +0.0 |
| hope_full | 3.45 | 4.7% | +0.2 | -1.7 | +1.6 | +0.0 |
| fixes_only | 3.42 | 4.8% | +0.4 | -0.9 | +1.1 | +1.6 |

- **CMS claim: negative.** cms_only destabilised (val 3.51 -> 4.31 at step
  2000 -> 3.94) and pruned its slow levels (w .05/.05). Multi-timescale
  memory without write gradient does not create retrieval here.
- **hope_full: negative on the primary (age 1 -1.7pp vs +10 bar).** Readback
  trained well below chance (2.53 vs 4.16) and val held, so writes became more
  retrievable by the readback's own contrastive test, but downstream layers did
  not learn to use them for the answer. The model zeroed the 128 level
  (w -0.000) and kept 512 faintly (.028).
- **Confound found:** batch 8 single-GPU gives 1/4 the lanes per step of
  v2_curr's 16 x 2 ranks (same tokens). That lowers the guessing prior (fresh
  9.2 -> ~4.7) in every new arm. It does not touch the contribution metric
  (persist vs fresh on the same checkpoint), but any rerun should match lanes.
- **fixes_only: negative (age 1 -0.9pp vs +10 bar).** Best val of the round
  (3.42) and readback at 1.01, yet no retrieval. All three arms negative.

### Verdict

The write gradient was necessary to test but not sufficient: with K=2 bptt
plus readback, writes become decodable (readback far below chance) but the
answer path never learns to use them. Neither Nested Learning's CMS nor the
detach fix produces cross-window retrieval at 134M / 393M tokens. Remaining
untested levers: slot/product-key state (lever c), a readback that targets
the ANSWER tokens rather than the raw values, larger K via activation
checkpointing, and matched lane count. om-model restarted after the round.
