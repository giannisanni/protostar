# hope-lite: Nested Learning's CMS + the write-gradient fix (pre-registered)

Source: Behrouz & Mirrokni, "Nested Learning: The Illusion of Deep Learning
Architectures" (NeurIPS 2025). Hope = self-modifying Titans + Continuum
Memory System (MLP levels at different update periods). The paper's
anti-forgetting argument is structural (slow levels keep what fast levels
overwrite). Our v2 rounds say the binding problem is different: TBPTT
detaches the state, so a probe's loss never reaches the projections that
WROTE the fact. This round tests both claims, separately and together.

## Arms (all init from `runs/v2_persist/ckpt_003000.pt`, same data and budget as v2_curr)

| arm | GPU | memory | bptt across windows | readback aux |
|---|---|---|---|---|
| hope_full | 0 (5060 Ti) | CMS 3 levels: period 32/128/512 tok, decay .99/.995/.999 | K=2, slow levels only | 0.1 |
| cms_only | 1 (5060 Ti) | same 3 levels | none (detached, as v2) | 0 |
| fixes_only | 2 (4060 Ti) | single level, period 32 | K=2 | 0.1 |

- CMS = independent (head-wise) variant, eq. 74; learned weighted sum, init
  w = [1, .1, .1]. Every level is seeded as a COPY of v2's trained memory
  (nested-CMS init), then diverges by period.
- Slow levels carry pending gradient across calls and update once per period
  (eq. 71); the 512 level updates once per window.
- Readback = InfoNCE (temp 0.1, 64 sampled keys): after each update, can the
  new state still retrieve the PREVIOUS update's values? Contrastive so it
  cannot be gamed by collapsing v. Chance = ln 64 = 4.16.
- Budget: 3000 steps x 131k tok = 393M tokens, window 512, batch 8, accum 32
  (same tokens/step as v2_curr's 16x8x2 ranks), cur_every 4, reset_prob
  .0625, muon .005 / adam 1e-4, warmup 100, decay from 2000.
- K=4 OOMs 16GB at batch 8 (measured); K=2 peaks 15.3GB. So bptt only
  directly trains age-1 probes. Ages 2+ show whether it generalises.
- New code verified bit-exact against the old FastMemory on the old config.

## Decision metrics (final checkpoints, currprobe ladder)

1. WRITE-GRADIENT claim (hope_full and fixes_only, age-1 contribution):
   - >= +10pp: the detach was the bottleneck; validated, raise K next
   - +4 to +10pp: partial; one round (K via activation checkpointing, or aux weight)
   - < +4pp: cross-window bptt at K=2 is not enough; documented negative
2. CMS claim (cms_only vs v2_curr, overall contribution):
   - >= +5pp overall: multi-timescale alone helps retrieval (paper's claim holds here)
   - < +5pp: CMS without write gradient does not fix it (our structural claim)
3. Interaction: hope_full minus fixes_only on age 2-3 and 4+. Positive (>= +4pp)
   = slow levels extend what bptt teaches beyond its K-window horizon.
4. Secondary: `oneshot.py --curriculum` mechanism (>=30 / 5-30 / <5%) and
   standard transfer, same thresholds as the curriculum round.

Report the full ladder for every arm, never one number.

## Guards

- fresh-memory FineWeb val <= 3.55 (v2_curr 3.46). The readback aux backprops
  into the backbone via wk/wv(h); a val rise in the aux arms alone points there.
- gate not collapsing; CMS weights w logged (slow levels pruned to ~0 = model
  rejected them; that is a result, not a bug).
- readback aux must end below 4.16 (chance), else the readback never trained.
- NaN guard active; units auto-resume from the newest checkpoint (every 500).

## RESULTS (2026-11-12)

Harness check first: v2_curr loaded as a 1-level MemoryStack reproduces its
ladder exactly (+2.2 / +1.4 / +1.4 / +6.3), so the stack eval path is sound.

| arm | val | fresh first-tok | contribution all | age 1 | age 2-3 | age 4+ |
|---|---|---|---|---|---|---|
| v2_curr (baseline) | 3.46 | 9.2% | +2.2 | +1.4 | +1.4 | +6.3 |
| cms_only | **3.94** (guard FAIL) | 4.8% | -0.1 | -0.2 | +0.0 | +0.0 |
| hope_full | 3.45 | 4.7% | +0.2 | -1.7 | +1.6 | +0.0 |
| fixes_only | 3.42 | 4.8% | +0.4 | -0.9 | +1.1 | +1.6 |

- **CMS claim: negative.** cms_only destabilised (val 3.51 -> 4.31 at step
  2000 -> 3.94) and pruned its slow levels (w .05/.05). Multi-timescale
  memory without write gradient does not create retrieval here.
- **hope_full: negative on the primary (age 1 -1.7pp vs +10 bar).** Readback
  trained well below chance (2.53 vs 4.16) and val held, so writes became more
  retrievable by the readback's own contrastive test, but downstream layers did
  not learn to use them for the answer. The model zeroed the 128 level
  (w -0.000) and kept 512 faintly (.028).
- **Confound found:** batch 8 single-GPU gives 1/4 the lanes per step of
  v2_curr's 16 x 2 ranks (same tokens). That lowers the guessing prior (fresh
  9.2 -> ~4.7) in every new arm. It does not touch the contribution metric
  (persist vs fresh on the same checkpoint), but any rerun should match lanes.
- **fixes_only: negative (age 1 -0.9pp vs +10 bar).** Best val of the round
  (3.42) and readback at 1.01, yet no retrieval. All three arms negative.

### Verdict

The write gradient was necessary to test but not sufficient: with K=2 bptt
plus readback, writes become decodable (readback far below chance) but the
answer path never learns to use them. Neither Nested Learning's CMS nor the
detach fix produces cross-window retrieval at 134M / 393M tokens. Remaining
untested levers: slot/product-key state (lever c), a readback that targets
the ANSWER tokens rather than the raw values, larger K via activation
checkpointing, and matched lane count. om-model restarted after the round.

## LOCATE: where retrieval breaks (2026-11-13, `accretion/locate.py`, no training)

403 age-1 probes, statement span ~14 tok, chance best-rank ~34 of 512.

| ckpt | ADDRESS rank / top-5 | STORE rank / top-5 | GRAD cross/within |
|---|---|---|---|
| v2_curr | 27 / 13% | 24 / 16% | 1.02 |
| fixes_only | 14 / 21% | 21 / 14% | 0.97 |
| hope_full (level 0) | 48 / 0% | 16 / 19% | 1.17 |

- GRAD is NOT the bottleneck once bptt is on: the cross-window gradient is as
  large as the within-window one.
- bptt did teach addressing (rank 27 -> 14) but it stays diffuse, and the
  read barely improves (24 -> 21): M q returns a blend of the whole window.
- Suspect, in the code: the write strength is per CHUNK (`lr = eta.mean`
  over 32 tokens, gradient summed with equal token weight), so the model
  cannot write the fact's tokens harder than filler. Every token interferes
  equally in one 640x640 map. Next lever: per-token write strength
  (GDN/Titans-style per-token beta), then a sparse/slot read if that is not enough.

## ROUND 2: per-token write strength (pre-registered 2026-11-14)

Change: `per_token=True` scales each token's inner gradient by its own eta
before the chunk sum (`err * eta_t`, lr folded in), instead of
`eta.mean(chunk) * sum(err k)`. Constant eta reproduces the old update
(tested). Everything else = fixes_only (1 level, chunk 32, K=2, readback .1).

| arm | GPUs | lanes/step | accum |
|---|---|---|---|
| pertoken_ddp | 0,1 DDP | 16 | 16 |
| pertoken | 0 | 8 | 32 |

Same 393M tokens, init, schedule. Run in sequence (ddp first), om-model stays on GPU 2.
pertoken vs fixes_only isolates the write change; pertoken_ddp adds matched-ish lanes.

Decision (currprobe age-1 contribution, + locate.py):
- >= +10pp: write strength was the bottleneck.
- +4 to +10pp: partial; check whether locate STORE sharpened (rank < 10) to pick next lever.
- < +4pp with ADDRESS/STORE sharp (rank < 5): read path is fine, answer path ignores it -> answer-targeted readback.
- < +4pp with STORE still diffuse: per-token writes are not enough -> slot/product-key state.
Guards unchanged (val <= 3.55, aux < 4.16, gate alive). Also report eta spread on fact vs filler tokens.

### ROUND 2 RESULT: pertoken_ddp (2026-11-14)

val 3.42 (guard ok). Ladder: all +0.7 | age 1 **-1.7** | age 2-3 +2.8 | age 4+ -0.5
(persist 5.2 / fresh 4.5 first-token). LOCATE: ADDRESS 14 / 19% top-5,
STORE 18 / 14%, GRAD 0.87. vs fixes_only: STORE 21 -> 18, ADDRESS unchanged.

**Negative** on the primary (age 1 < +4pp), and STORE is still diffuse, so per

the state itself (slot/product-key, or a deep MLP memory). Note: fresh stays
~4.5% at 16 lanes, so the lane-count story does not explain v2_curr's 9.2%.
pertoken (8 lanes, the clean ablation) still running.

## ROOT CAUSE: the curriculum erased in-context copying (2026-11-14, `accretion/ceiling.py`)

Standing rule applied late: the curriculum probes were never calibrated
against the backbone. First-token accuracy on the age-1 probes with the fact
put back IN context (memory reset), by distance from statement to question:

| ckpt | 0 | 16 | 32 | 64 | 128 | 256 | ~450 | no fact |
|---|---|---|---|---|---|---|---|---|
| gdn (base) | 16.9 | 13.9 | 10.4 | 8.9 | 5.7 | 6.5 | 5.0 | 4.0 |
| v2_persist | **31.8** | 26.1 | 22.3 | 12.9 | 7.9 | 2.7 | 2.7 | 2.5 |
| v2_curr | **3.0** | | | | | | 4.2 | 5.0 |
| pertoken_ddp | **4.2** | | | | | | 3.0 | 4.7 |

1. Every curriculum-trained checkpoint lost in-context copying of fact
   answers (31.8% -> 3-4%, = the no-fact floor; P(" K") for "...mayor of
   Blafro is Kresut ... Answer:" 13.8% -> 0.0%). Cause: the anti-leak
   invariant means a fact answer is NEVER visible to attention during
   training; memory never delivered either, so the optimum was the name
   prior. The "fresh 9.2%" of v2_curr was that prior, not retrieval.
2. Even before the curriculum, the 134M backbone only uses a novel name
   within ~64 tokens. Cross-window probes sit >= 513 tokens away.
3. So every memory arm was asked to feed an answer circuit the training had
   switched off. All rounds' negatives (v2_curr, CMS, bptt, per-token) are
   confounded by this; none of them falsify the memory designs.

## ROUND 3: near probes (pre-registered 2026-11-14)

`FactStream(near=.15)`: some emissions re-ask a fact still in the same window
(logged "near", ~1 per 2 far probes; far probes still never leak, tested;
near=0 is bit-identical to before). Arm `pertoken_near` = pertoken config,
DDP GPUs 0,1, 16 lanes, accum 16, same budget/init.

Decision (final ckpt):
- Ceiling guard: NEAR (distance 0) >= 25%, else near probes did not keep
  the copy circuit and the round is uninterpretable.
- Primary: currprobe age-1 contribution >= +10pp pass / +4-10 partial / < +4
  negative (then: deep MLP memory or slots, on top of near probes).
- Also report contribution / NEAR ceiling, and locate.py.
- Guard val <= 3.55.

### ROUND 3 RESULT: pertoken_near (2026-11-15)

val 3.42 (ok). Ceiling guard PASS: in-context 95.0% at distance 0, 94.8% at
256, 89.1% at ~450 (no fact 6.7%); was 31.8% -> 2.7% before. The answer
circuit is now strong and long-range.
Ladder: all +2.0 | age 1 **+3.5** | age 2-3 +1.4 | age 4+ +0.5 (persist 13.0 / fresh 9.5 at age 1).
LOCATE: ADDRESS 18 / 14%, STORE 18 / 13%, GRAD 0.67.

**Negative by the pre-registration (age 1 < +4pp)**, best of all rounds but
~1.5 SE. Contribution / ceiling = 3.5 / 95 = 4%. This round is the first
clean test: the answer path works, so what fails is the memory itself. The
640x640 matrix read (STORE rank 18) still returns a blend, not the fact.
Next lever is now unconfounded: slot memory (carry the previous window's
keys/values, or a product-key table) and/or a deep MLP memory, on top of
near probes.

## ROUND 4: slot memory (pre-registered 2026-11-15)

`accretion/slots.py`: the memory stores every token's (k, v) from earlier
windows as-is (FIFO 4096 tokens = 8 windows) and reads by 10-head softmax
attention with a null slot; pre-LayerNorm on its input. Same layer-12 MAG
gate, init (v2_persist), near=.15 curriculum, K=2, DDP 16 lanes, budget.
Only the memory type differs from pertoken_near (round 3).

Decision (final ckpt, currprobe + ceiling):
- age-1 contribution >= +10pp: slots fix cross-window recall; the matrix was
  the bottleneck. Then: ages 2-3/4+ show whether FIFO capacity is used.
- +4 to +10pp: partial (read sharper than the matrix but the answer path
  under-uses it); try stronger gate init / more bptt.
- < +4pp: even uncompressed storage is not read -> the problem is training
  signal (gate/readout), not capacity. Next: a probe-targeted aux loss.
- Guards: ceiling NEAR >= 25%, val <= 3.55.

### ROUND 4 RESULT: slots_near (2026-11-15)

val 3.53 (guard ok, but worse than round 3's 3.42). Ceiling 95.3% (ok).
Ladder: all +0.4 | age 1 **+1.2** | age 2-3 -0.2 | age 4+ +0.5. **Negative.**
Diagnostic on 403 age-1 probes: gate at the probe = **1.000** (fully open),
fast_proj norm 197 (grew from ~0.03): the branch is used heavily, but NOT
for facts. Slot attention mass on the fact span 3.9% vs 2.7% chance; best
rank of a fact token 20 (matrix: 18).

**Verdict:** storage was never the bottleneck. Both memories fail at
ADDRESSING: the query at "Answer:" does not find the statement's keys,
while the backbone's own attention does exactly that at 89-95%. A fresh
memory has to learn retrieval from sparse probe gradients and instead
learns to inject generic context. Next: reuse the circuit that already
works, i.e. carry the previous window's K/V into the EXISTING attention
layers (Transformer-XL cache), so cross-window recall needs no new
addressing to be learned.
